# บันทึกข้อความราชการไทย (โรงเรียนพูลเจริญวิทยาคม)

สร้าง/แก้บันทึกข้อความภายในให้ถูกระเบียบงานสารบรรณและแบบของโรงเรียน ค่าพิกัด
และโครงสร้างในสกิลนี้สกัดจากเอกสารจริงของโรงเรียน (ดูตัวอย่างที่แนบมาใน `examples/`)


> **สกิลที่เกี่ยวข้อง (ต้องใช้ด้วยกัน)**: `thai-smart-form-apps` — กติกาแอปกรอกแบบฟอร์ม/พรีวิว A4 · `thai-official-memo` — โครงบันทึกข้อความ · `thai-doc` — มาตรฐานตัวอักษร/ตาราง

## When to Use (เมื่อไหร่ใช้)

- บันทึกข้อความไปราชการ / ขออนุมัติเดินทาง
- บันทึกข้อความรายงานผลการไปราชการ (ต้องมีภายในวันที่ระบุในบันทึกขอ)
- บันทึกข้อความส่งข้อสอบวัดผลปลายภาค/กลางภาค
- บันทึกชี้แจง (เช่น ชี้แจงการไม่ลงชื่อกลับ) · บันทึกการสอนแทน · บันทึกส่งเอกสาร

ไม่ใช้กับ: โครงการ (→ `thai-project-proposal`) · ข้อสอบ (→ `thai-exam-format`) · คำสั่ง/ประกาศโรงเรียน

## Prerequisites

- รันสคริปต์ด้วย `py -3.12` เท่านั้น (มี `python-docx 1.2.0` / `pythainlp 5.3.7` / `pymupdf 1.28.2`) — python 3.14 ของ Hermes ไม่มี python-docx
- ตราครุฑ: `assets/logo-krut.png` (สูง 1.5 ซม.)
- ตัวอย่างเอกสารที่ส่งจริง: `examples/` (แบบเปล่า / การสอนแทน / ส่งข้อสอบ)

## ลำดับเนื้อความ (3 ย่อหน้า)

1. **อ้างต้นเรื่อง** — ตามที่/ด้วย หน่วยงานใด แจ้งอะไร เลขที่หนังสือ ลงวันที่ เรื่อง ณ สถานที่ วันเวลา (คัดลอกเลขอ้างอิงจากหนังสือจริงเท่านั้น ห้ามแต่งเลข)
2. **สาระของเรื่อง** — สิ่งที่ทำ/ขอ/รายงาน พร้อมรายละเอียด จำนวน งบประมาณ ผู้เข้าร่วม
3. **ปิดท้าย** — `จึงเรียนมาเพื่อโปรดพิจารณา` (ขออนุมัติ) / `จึงเรียนมาเพื่อโปรดทราบ` (รายงาน) / `จึงเรียนมาเพื่อโปรดทราบและพิจารณา` (ส่งเรื่อง)

## กระบวนการเมื่อได้ "กฎรูปแบบละเอียด" จากผู้ใช้

ผู้ใช้สกิลนี้ตรวจเอกสารด้วยตาเปล่าและจับความคลาดเคลื่อนระดับพิกเซลได้ — อย่ารีบแก้โค้ด
และอย่าถือว่าการแก้แอปที่ถูกเอ่ยถึงคือจบงาน

1. **วัดของจริงก่อน** — เปิดเอกสารที่เรนเดอร์จริง วัดระยะที่เกี่ยวข้องแล้วรายงาน **ค่าที่วัดได้**
   (ไม่ใช่ค่าที่ตั้งใจไว้ในโค้ด) พร้อมชี้ว่าแต่ละแอปต่างกันแค่ไหน
2. **รายงาน + ถามจุดที่ต้องตัดสิน** — หน่วย (px/pt) · เพิ่มจากระยะเดิมหรือแทนที่ · ขอบเขตเอกสาร ·
   Word ต้องตรงกับพรีวิวไหม · ใน Word ให้เป็นย่อหน้าว่างหรือ spacing — เสนอคำตอบของเราแต่ละข้อ
3. **รออนุมัติแล้วค่อยลงมือ** (ผู้ใช้มักตอบ "เอาตามที่เสนอ" หรือแก้บางข้อ)
4. **แก้ให้ครบทุกทางออกและทุกเอกสาร** — ตั้งกลไกกลาง + ประกาศเป็นเอกสารมาตรฐานในเรโป
   (เช่น `docs/standards/…`) เพื่อไม่ให้รอบหน้าพลาดซ้ำ
5. **รายงานกลับเป็นตาราง**: เอกสารอะไร · ไฟล์ไหน · ค่าที่วัดได้ · จำนวนหน้าเปลี่ยนไหม ·
   และระบุตรง ๆ ถ้าบางจุดยืนยันได้แค่ระดับเทมเพลต/ไฟล์ Export

## ระยะบรรทัดว่างมาตรฐาน (blank-line rule) — ห้ามข้าม

บันทึกข้อความทุกฉบับต้องมี **บรรทัดเปล่าสูง 8px** แทรกที่ 3 จุดนี้เสมอ:

1. **ก่อน** บรรทัด `เรียน ......`
2. **หลัง** บรรทัด `เรียน ......`
3. **ก่อน** บรรทัด `จึงเรียนมาเพื่อ...`

หน่วย: `8px = 6pt = 120 twips` (ค่านี้ใน `.docx` คือ `w:before/w:after="120"`) — ถ้าผู้ใช้ระบุหน่วยอื่น
ให้ใช้หน่วยนั้น แล้วรายงานว่าใช้หน่วยอะไร **อย่าสลับ 8px กับ 8pt** (ต่างกันเกือบ 2 เท่า)

**ต้องตรงกันทั้ง 3 ทางที่เอกสารออกไป** — นี่คือจุดที่งานพลาดซ้ำบ่อยที่สุด เพราะเอกสารเดียวถูกสร้างหลายทาง
และแต่ละทางมีระยะของตัวเอง:

| ทางออก | ที่แก้ |
|---|---|
| พรีวิวบนจอ | CSS ของแผ่น A4 (`.memo-salutation`, `.memo-closing`, `.memo-paragraph`) |
| พิมพ์ / PDF | CSS ชุดเดียวกัน (ถ้ามี `@media print` ที่ override margin ต้องแก้ที่นั่นด้วย) |
| Word `.docx` | ตัวสร้าง docx แยกไฟล์ — ตั้ง `before`/`after` เป็น twips |

ทำเป็น **element/คลาสกลาง** (เช่น `.memo-blank-line` + ตัวแปร CSS) ไม่ใช่พึ่ง `margin` ของบรรทัดข้างเคียง
เพราะการไปปรับ margin เพื่อจัดหน้าอื่นจะลบ 8px หายเงียบ ๆ โดยไม่มีใครรู้

**ระวัง margin collapse:** ใส่ element กลางเข้าไประหว่างสองบล็อกแล้ว margin ของสองข้างจะไม่ยุบกันอีก
ช่องว่างที่เห็นจึงกลายเป็น "margin บน + 8px + margin ล่าง" (โตเกิน 8px เงียบ ๆ) ให้เติมกฎ
`.memo-blank-line + * { margin-top: 0 !important }` แล้วช่องว่างจะเท่ากับ margin ของบล็อกก่อนหน้า + 8px เป๊ะ
และวัดซ้ำเพื่อยืนยัน ไม่ใช่คำนวณในหัว

**ตรวจรับ (วัดจริง ไม่ใช่ดูด้วยตา):**

1. พรีวิว: `getComputedStyle(el).height` ของทุก `.memo-blank-line` ต้องเป็น `8px` และวัดช่องว่างจริงด้วย
   `getBoundingClientRect` ของบรรทัดก่อน/หลัง **หารด้วย scale ของแผ่น** (แผ่น A4 ถูก `zoom`/`transform` อยู่
   ค่าที่อ่านได้จึงต้องแปลงกลับเป็น px บนกระดาษก่อนเทียบ)
2. พิมพ์/PDF: เปิด `Emulation.setEmulatedMedia(media='print')` แล้ววัดซ้ำ — ต้องยังได้ 8px
3. Word: **ห้ามเชื่อโค้ด ต้องเปิดไฟล์ที่สร้างจริง** → `scripts/verify_docx_spacing.py <ไฟล์.docx>`
   (แตก `word/document.xml` แล้วอ่าน `w:spacing` ของย่อหน้า `เรียน` / `จึงเรียนมาเพื่อ`)
4. **จำนวนหน้าเดิมไม่เปลี่ยน** — เติม 3 จุด = +24px อาจดันเอกสารที่เต็มหน้าให้ล้นเป็น 2 หน้า
   นับ `.a4-sheet` (หรือ `<w:br w:type="page"/>`) ก่อน/หลัง

**กับดักของ Word แบบเทมเพลต:** แอปที่สร้าง .docx ด้วยการเติมข้อความลงไฟล์เทมเพลต (`PizZip`/`docxtemplater`)
จะ **ไม่ได้รับ** ค่า spacing จาก JS เลย เพราะระยะอยู่ในเทมเพลต — ต้องแก้ `word/document.xml` ภายใน
`.docx` เทมเพลตโดยตรง (เพิ่ม/บวก `w:before`/`w:after` ใน `<w:pPr><w:spacing .../>` ของย่อหน้าเป้าหมาย)
แล้วตรวจด้วยสคริปต์เดียวกัน — วิธีอ่าน/เขียน XML ให้ปลอดภัย (regex ที่ต้องใช้, การเขียน zip กลับ,
หน่วย twips, และการดึงไฟล์จริงออกมาเมื่อปุ่ม Export ถูก gate ด้วยฟอร์ม) อยู่ใน
`references/docx-xml-editing.md`

**ถ้าปุ่ม Export ใช้งานไม่ได้ในสถานะทดสอบ** (ซ่อนจนกว่าจะเลือกครู/กรอกฟอร์มครบ) ห้ามสรุปว่า "ตรวจไม่ได้"
ให้เรียกตัวสร้างที่หน้าเว็บ expose ไว้ (`window.<BUILDER>.buildMemoDocx({...})` → Blob → anchor download
d้วย `Browser.setDownloadBehavior`) แล้วตรวจไฟล์นั้น หรือรายงานตรง ๆ ว่า ยืนยันได้เพียงระดับเทมเพลต/โค้ด

## Thai PW Hub — แอปที่ออกร่าง "บันทึกข้อความ" ต้องยึดสกิลนี้ทันที (ไม่ต้องรอสั่ง)

ถ้าผู้ใช้ขอ/มีเอกสารชนิด **บันทึกข้อความ** ใน Thai PW Hub (เช่น `apps/smart-form-filler` เทมเพลต `research-memo`) ให้ใช้สเปกในสกิลนี้ทันที — ห้ามใช้โครง memo แบบง่าย ๆ ที่มีแค่ "บันทึกข้อความ + ส่วนราชการ + เรียน + ลงชื่อ" เพราะผู้ใช้ถือว่าผิดหลัก

**ค่าที่ต้องมีจริงในงาน (ตรวจได้จาก DOM/ไฟล์ที่สร้าง):**

| องค์ประกอบ | ค่า | ตรวจอย่างไร |
|---|---|---|
| ตราครุฑ | สูง 1.5 ซม. ในตาราง 3 คอลัมน์ (3.00 / 9.92 / 3.53 ซม.) ไม่มีเส้น | `<img>` height = 56.7px · DOCX มี `word/media/` + `w:drawing` |
| "บันทึกข้อความ" | **20 pt หนา** กึ่งกลาง (คอลัมน์กลาง) | `w:sz=40` · CSS 26.6667px |
| ที่ / วันที่ | วันที่อยู่ตำแหน่งคงที่ **50%** ของความกว้างเนื้อหา ไม่เลื่อนตามความยาวเลขที่ | ใช้ inline-block 50% (พรีวิว) / ตารางไร้เส้น 4796-4796 twips (DOCX) |
| เรื่อง | คำว่า `เรื่อง` หนาเทินั้น ค่าธรรมดา | `w:b` เฉพาะ label |
| เส้นคั่น | ย่อหน้าว่างมีเส้นล่าง `w:sz="6"` ภายใต้บรรทัดเรื่อง | `pBdr` 1 จุด |
| เรียน | label หนา ค่าธรรมดา | |
| เนื้อความ | ย่อหน้าเยื้องบรรทัดแรก **2.5 ซม.** | `w:firstLine="1417"` · CSS 94.49px |
| ลงชื่อ | เยื้อง **4.5 ซม.** (ตารางไร้เส้น 4.5/11.5) และ **ภายในบล็อกจัดกลางทั้ง 3 บรรทัด** (ลงชื่อ / (ชื่อ) / ตำแหน่ง อยู่แกนเดียวกัน) | DOCX `w:jc=center` ทุกบรรทัด ในเซลล์ขวาของตาราง 4.5/11.5 |
| ช่องความเห็น | หัวข้อหนา · ติ๊กเยื้อง 2.5 ซม. · **ห้ามมีกรอบ** | ไม่มี `w:tblBorders` ในส่วนนี้ |
| ระยะขอบ | บน 2.0 · ล่าง 1.27 · ซ้าย 2.54 · ขวา 2.0 ซม. | `pgMar top=1138 bottom=720 left=1440 right=1138` |

**กับดักที่เคยพลาด (สำคัญ):** `.a4-sheet div { margin: 0 }` ทำให้กฎ `.memo-sign { margin-left: 4.5cm }` ถูกทับเงียบ ๆ → ต้องเขียน `.a4-page .memo-sign` ให้ specificity สูงกว่า แล้ววัด `rect.left - pageBody.left` ยืนยันเป็นพิกเซล

**ให้จบในหน้าเดียวเมื่อทำได้:** บล็อกลงนาม 3 บรรทัด ใช้ `w:line="240" w:lineRule="exact"` และ `before` ของหัวข้อความเห็น **140 twips** — ห้ามใช้ 120 เพราะจะทำให้นับ `w:before="120"` ในไฟล์ได้ 6 แทน 3 แล้วตรวจบรรทัดเปล่า 8px อัตโนมัติไม่ได้

## Variant

| ประเภท | เนื้อความ | บล็อกลงชื่อ | เอกสารแนบ |
|---|---|---|---|
| ไปราชการ | ขออนุมัติ + ขอรับรองประโยชน์ + กำหนดวันรายงานผล | ผู้ขอ → ความเห็นรอง ผอ. → ความเห็น ผอ. | กำหนดการ/หนังสือเชิญ |
| รายงานผลไปราชการ | ตามที่ + สรุปสิ่งที่ได้ + ข้อเสนอ | ผู้รายงาน → รอง ผอ. → ผอ. | รูป/องค์ความรู้ (ถ้ามี) |
| ส่งข้อสอบ | อ้างข้อกำหนดฝ่ายวิชาการ + ส่งต้นฉบับตามแบบสรุป | หัวหน้ากลุ่มสาระฯ เท่านั้น | แบบสรุปการส่งข้อสอบ (หน้า 2) |
| ชี้แจง | เหตุการณ์ + สาเหตุ + แนวแก้ไข | ผู้ชี้แจง → ผอ. | หลักฐาน (ถ้ามี) |
| การสอนแทน | คาบ/วิชา/ชั้น + ครูผู้สอนแทน + เหตุผล | ผู้จัดทำ | ตารางสอน |

บล็อกความเห็นผู้บังคับบัญชา: ตาราง 2 คอลัมน์ (4.5 / 11.5 ซม.) ไม่มีเส้นขอบ · **ทุกบรรทัดในบล็อกจัดกลาง (jc=center) ให้ ลงชื่อ / (ชื่อ) / ตำแหน่ง อยู่แกนเดียวกัน** — ห้ามใช้ `left_indent` ไล่บรรทัดทีละค่า

## รูปแบบ DOCX

- `TH Sarabun New` 16 pt เนื้อหา · บันทึกข้อความ 20 pt · สีดำ `#000000` · Line spacing 1.0 · Space before/after 0 pt (ยกเว้นเส้นคั่น/ช่องลงชื่อ)
- แทรก ZWSP ระหว่างคำไทยทุก run (`pythainlp.word_tokenize(engine='newmm')` แล้ว join ด้วย `\u200b`) — ห้ามแทรกกลางคำระหว่างพยัญชนะกับสระ/วรรณยุกต์/ทัณฑฆาต
- คลังเดิมตั้ง `noProof` + `hideSpellingErrors` + `lang=th-TH` (ต่างจากงานโครงการที่ห้าม `noProof` — งานคนละแบบ อย่าสลับ)
- อย่าใช้ Tab หรือเคาะวรรคจัดแนว ใช้ left_indent / first_line_indent / ตารางไม่มีเส้นขอบ
- สร้างเฉพาะ `.docx` ยกเว้นผู้ใช้สั่ง PDF ชัดเจน (ถ้าต้องพรีวิว ให้ render เป็นภาพเพื่อตรวจก่อนส่ง)

## ข้อมูลผู้ลงนาม

ไม่ hardcode ชื่อผู้ลงนาม · ใช้ชื่อ-ตำแหน่งตามที่ผู้ใช้ระบุในงานนั้น ถ้าไม่ระบุให้ใช้โปรไฟล์เจ้าของเครื่องจากสกิล `thai-doc` (`skill_view('thai-doc', 'references/user-profile-th.md')`)
ชื่อหัวหน้ากลุ่มสาระฯ ต้องสะกด **นายรามิล ปัญญพัทธ์** เท่านั้น (ห้าม ปัญญะพัฒน์ / ปัญญาพัทธ์)

## Pitfalls

1. **วันที่เป็น ค.ศ.** — ต้องเป็น พ.ศ. และวัน/เดือนต้องตรงกับหนังสืออ้างอิง
2. **แต่งเลขที่หนังสือ/ศธ** — ต้องคัดลอกจากต้นเรื่องจริง ถ้าไม่มีให้เว้นจุดไข่ปลา
3. **เรื่องตัวหนาทั้งบรรทัด** — มีแต่คำว่า `เรื่อง` ที่ bold
4. **ลืมบล็อกความเห็น ผอ.** ในบันทึกขออนุมัติ — แบบโรงเรียนมี 2 ชั้น (รอง ผอ. → ผอ.)
5. **เลขอ้างอิง/จำนวนเงินในเนื้อความไม่ตรงกับเอกสารแนบ** — ตรวจก่อนส่ง
6. **ลืมบรรทัดเปล่า 8px ก่อน/หลัง `เรียน` และก่อน `จึงเรียนมาเพื่อ`** — และถ้าแก้ ต้องแก้ทั้งพรีวิว พิมพ์
   และตัวสร้าง .docx (แก้ทางเดียว = ไฟล์ Word ที่ครูส่งต่อยังผิด)
7. **ของเก่าที่ "ดูเหมือนทำแล้ว" แต่ผิดหน่วย** — ในระบบนี้เคยเจอ `height:8pt` (10.67px) และ `blankPara(16)`
   (ย่อหน้าว่าง 8pt) ทั้งที่ต้องการ 8px ก่อนแก้ให้ `grep -rn 'height:8pt\|blankPara(\|8pt' ` ในแอปนั้นก่อน
   แล้วแทนที่ด้วยกลไกกลาง ไม่ใช่เพิ่มของใหม่ทับของเก่า
8. **แก้แค่แอปที่ผู้ใช้พูดถึง** — กฎรูปแบบเอกสารของโรงเรียนใช้กับ *ทุก* แอปที่ออกร่างเอกสารชนิดเดียวกัน
   (ใน Thai PW Hub: บันทึกข้อความ · ขออนุมัติผลการเรียน ร · สอบซ่อม · สรุปการส่ง · แบบเสนอ/ดำเนินโครงการ)
   สวีปให้ครบทุกตัวแล้วรายงานเป็นตารางว่าจัดการเอกสารอะไรไปบ้าง
9. **รายงานว่า "ตรวจแล้ว" โดยไม่ได้เปิดไฟล์ที่ผู้ใช้จะได้** — ตรวจจากโค้ดไม่นับ ให้ดาวน์โหลด/สร้างไฟล์จริง
   แล้วเปิดอ่าน `w:spacing` หรือวัดในหน้าที่เรนเดอร์จริงเท่านั้น

# เขียนโครงการสถานศึกษา โรงเรียนพูลเจริญวิทยาคม

จัดทำ/แก้ไข/ตรวจโครงการของโรงเรียนให้ตรงแบบฟอร์มโรงเรียน ใช้ภาษาไทยราชการ
กระชับ และตรวจความสอดคล้องกับเอกสารจัดทำแผนก่อนส่งมอบ ทำงานกับไฟล์ `.docx`
เป็นหลัก สกิลนี้เป็นชุดปิดในตัว: คู่มือ ข้อมูลแผน สคริปต์ และโลโก้ อยู่ในโฟลเดอร์สกิลทั้งหมด

## When to Use (เมื่อไหร่ใช้)

- เขียนโครงการใหม่ หรือแก้โครงการเดิมของโรงเรียนพูลเจริญวิทยาคม
- ตรวจว่าโครงการสอดคล้องกับเอกสารจัดทำแผนปีการศึกษา (กลยุทธ์/โครงการหลัก/นโยบาย/มาตรฐาน/เป้าหมาย)
- ตรวจงบประมาณ ตัวชี้วัด หรือความครบของหัวข้อก่อนส่ง ผอ.

ไม่ใช้กับ: บันทึกข้อความ (→ `thai-official-memo`) · ข้อสอบ (→ `thai-exam-format`) · รายงานผลโครงการ (ใช้ `thai-doc` + รูปแบบรายงาน)

## Prerequisites

- รันสคริปต์ด้วย `py -3.12` เท่านั้น (มี `python-docx 1.2.0` / `pythainlp 5.3.7` / `pymupdf 1.28.2`) — python 3.14 ของ Hermes ไม่มี python-docx
- ใช้ `terminal(command="py -3.12 <SKILL_DIR>/scripts/generate_project_docx.py", workdir=<โฟลเดอร์งาน>)` โดยมี `school logo.png` อยู่ในโฟลเดอร์งาน
- โลโก้โรงเรียน: `assets/school-logo.png`
- เอกสารอ้างอิงแผนปี: `references/plan-2569-source.md` (ไม่ต้องเปิด PDF ใหญ่)

## กฎแหล่งข้อมูล (ห้ามแต่ง)

ใช้ข้อมูล 3 แหล่งเท่านั้น

1. **แบบฟอร์มโครงการของโรงเรียน** → โครงสร้างเอกสาร
2. **เอกสารจัดทำแผนปีการศึกษา** → กลยุทธ์ โครงการหลัก นโยบาย มาตรฐาน เป้าหมาย (`references/plan-2569-source.md`)
3. **ข้อมูลเฉพาะที่ผู้ใช้ให้มา** → กิจกรรม กลุ่มเป้าหมาย ระยะเวลา งบประมาณ ผู้รับผิดชอบ

ห้ามแต่งชื่อกลยุทธ์ โครงการหลัก นโยบาย สพฐ. Quick Win มาตรฐานการศึกษา นโยบายโรงเรียน หรือเป้าหมายโรงเรียนขึ้นเอง และห้ามดัดแปลงถ้อยคำต้นฉบับของหัวข้อเหล่านี้

## ลำดับตรวจความสอดคล้อง (ก่อนเขียน)

หลักการ: **เลือกเท่าที่จำเป็นและตรงกับโครงการ** ไม่คัดลอกทุกข้อมาใส่

| ลำดับ | หัวข้อ | เกณฑ์ตัดสิน |
|---|---|---|
| 1 | กลยุทธ์ | ตรงกับกลุ่มผู้รับประโยชน์และลักษณะงาน |
| 2 | โครงการหลัก | มีชื่ออยู่ในรายการเอกสารจัดทำแผน |
| 3 | นโยบาย สพฐ. | เลือกข้อหลัก + เฉพาะข้อย่อยที่กิจกรรมตอบได้จริง |
| 4 | Quick Win | ตรงผู้รับประโยชน์ — โครงการนักเรียนไม่เลือกข้อที่มุ่งพัฒนาครู เว้นแต่มีกิจกรรมพัฒนาครูจริง |
| 5 | มาตรฐานการศึกษา | เชื่อมกับผลลัพธ์ที่วัดได้ (ทักษะอาชีพ/ความเป็นไทย/สุขภาวะ/คิดแก้ปัญหา/การจัดการเรียนรู้) |
| 6 | นโยบายโรงเรียน + เป้าหมายโรงเรียน | โครงการสนับสนุนโดยตรงเท่านั้น |

ข้อย่อย: **แสดงเลขข้อหลักก่อนเสมอ** แล้วตามด้วยเฉพาะข้อย่อยที่เกี่ยวข้อง ห้ามยกมาทั้งหมดเพื่อให้ดูครอบคลุม

## โครงสร้างเอกสาร (ตามแบบฟอร์มโรงเรียน)

โรงเรียน · กลุ่มงาน · ปีการศึกษา · ภาคเรียน → ชื่อกลยุทธ์ → ชื่อโครงการหลัก → ชื่อโครงการ → ลักษณะโครงการ (ใหม่/ต่อเนื่อง) → นโยบาย สพฐ. → นโยบาย Quick Win → มาตรฐานการศึกษาขั้นพื้นฐาน → นโยบายโรงเรียน → เป้าหมายโรงเรียน → 1. หลักการและเหตุผล → 2. วัตถุประสงค์ → 3. เป้าหมายเชิงปริมาณและเชิงคุณภาพ → 4. กิจกรรมและการดำเนินการ → 5. ผู้รับผิดชอบโครงการ → 6. หน่วยงาน/บุคลากรที่เกี่ยวข้อง → 7. งบประมาณ → 8. รายละเอียดการใช้วัสดุและงบประมาณดำเนินงาน → 9. การประเมินผล → ช่องลงนามและพิจารณาอนุมัติ

## กติกาการเขียนรายหัวข้อ

**1. หลักการและเหตุผล** — ความเรียง 3 ย่อหน้า รวม ~10–15 บรรทัด
1. บริบทการศึกษา ความสำคัญ และความจำเป็นต่อผู้เรียน
2. บริบท/เป้าหมายโรงเรียน เชื่อมกับนโยบายและมาตรฐานที่เลือก
3. ขึ้นต้นด้วย **"ด้วยเหตุนี้"** → เหตุผลที่จัดทำ กิจกรรมที่จะทำ และผลที่คาดว่าจะได้

ทุกข้อความต้องนำไปสู่กิจกรรมจริง ห้ามกล่าวอ้างผลลัพธ์ที่โครงการไม่ได้ทำ

**2. วัตถุประสงค์ / 3. เป้าหมาย**
- วัตถุประสงค์ใช้คำกริยาวัดผลได้ (พัฒนา ส่งเสริม ปลูกฝัง ให้ความรู้ ฝึกปฏิบัติ จัดทำแนวทาง) และจับคู่กับกิจกรรม+ตัวชี้วัดได้ทุกข้อ
- เชิงปริมาณ: ระบุผู้รับประโยชน์ จำนวน/ร้อยละ และช่วงเวลาหรือจำนวนครั้ง **ตรวจยอดรวมด้วยการคำนวณจริง**
- เชิงคุณภาพ: การเปลี่ยนแปลงที่คาดหวัง (ความรู้ ทักษะ พฤติกรรม เจตคติ) ห้ามใช้ถ้อยคำกว้างที่วัดไม่ได้

**4. กิจกรรมและการดำเนินการ** — ตาราง 3 คอลัมน์ `กิจกรรม | ระยะเวลา | ผู้รับผิดชอบ` แบ่งขั้นเตรียมการ / ขั้นดำเนินการ / ขั้นติดตามและประเมินผล
- กิจกรรมต้องสอดคล้องวัตถุประสงค์ทุกข้อ ระบุระดับชั้น กลุ่มเป้าหมาย เวลา ผู้รับผิดชอบให้ตรวจย้อนกลับได้
- ถ้ามีเอกสารกำหนดการแยก ชื่อกิจกรรม วันเวลา และจำนวนผู้เข้าร่วมต้องตรงกับโครงการหลัก
- ห้ามเหลือข้อความร่าง เช่น "รอรายละเอียดเพิ่มเติม"

**7. งบประมาณ** — ใช้คำว่า "งบประมาณ" เฉย ๆ ห้ามเติม "(โดยประมาณ)"
หัวตารางครบ: ที่ | รายการ | จำนวน/หน่วย | ราคา/หน่วย | งบประมาณ (บาท) + แถวรวมเป็นเงิน
ตรวจ 4 สมการทุกครั้ง: จำนวน × ราคา/หน่วย = งบรายการ · ผลรวมรายการย่อย = ยอดหมวด · ผลรวมทุกหมวด = ยอดโครงการ · จำนวนผู้เข้าร่วม × ค่าใช้จ่ายต่อคน = รายการอาหาร/วัสดุ
แหล่งเงินและประเภทงบประมาณต้องตรงกับที่ได้รับจัดสรร · ถ้าผู้ใช้ยืนยันรายการเพิ่ม ถือว่าถูกต้องและปรับยอดรวมให้ตรงทุกจุด

**9. การประเมินผล** — ตาราง 3 คอลัมน์ `ตัวชี้วัดความสำเร็จ | วิธีประเมิน | เครื่องมือประเมิน`
ตัวชี้วัดต้องจับคู่วัตถุประสงค์และมีเกณฑ์ (ร้อยละ/จำนวน/คะแนนเฉลี่ย/ระดับคุณภาพ) หลีกเลี่ยงการวัดแค่ความพึงพอใจเมื่อโครงการมีผลลัพธ์ด้านความรู้หรือทักษะ
เครื่องมือ: เข้าร่วม → แบบบันทึกเวลา/รายชื่อ · ความรู้ → ทดสอบก่อน–หลัง · ทักษะ/พฤติกรรม → แบบสังเกต/รูบริก · วางแผนศึกษาต่อ/อาชีพ → ใบงาน+แบบสะท้อน · ความพึงพอใจ → แบบประเมิน

## รูปแบบ DOCX

- `TH Sarabun New` ทั้งเอกสาร เนื้อหา 16 pt (หัวข้อปรับให้เด่นได้แต่ต้องฟอนต์เดียวกัน)
- แทรก Zero-width space (`\u200b`) ระหว่างคำไทย **ทุกส่วน**: นอกตาราง ในตาราง หัวกระดาษ ท้ายกระดาษ กล่องข้อความ — ห้ามลบ ห้ามเปลี่ยนคำหรือความหมาย
- ตั้งภาษา proofing เป็น `th-TH` และ **ห้ามใช้ `noProof`** ในงานโครงการ (ต่างจากงานบันทึกข้อความ/ข้อสอบ) เพื่อให้ผู้ใช้ยังเห็นคำที่อาจสะกดผิด
- รักษาแบบฟอร์มเดิมของโรงเรียนเมื่อแก้เอกสารเดิม แก้เฉพาะข้อความที่ได้รับอนุมัติ
- ใช้ตารางจริงกับกิจกรรม/งบประมาณ/ประเมินผล คงหัวตาราง ทุกช่องมีข้อมูล ความกว้างคอลัมน์ไม่ล้น ไม่ใช้การเคาะวรรคจัดแนว
- กระบวนการ: อ่านต้นฉบับ → แก้แบบรักษารูปแบบ → ตรวจโครงสร้างข้อความ/ตาราง → เรนเดอร์เป็นภาพ → ตรวจทุกหน้า → แก้+เรนเดอร์ซ้ำ

## Pitfalls

1. **แต่งชื่อนโยบาย/มาตรฐานขึ้นเอง** — ผิดกฎเหล็กที่สุดของงานนี้ อ้างจาก `plan-2569-source.md` เท่านั้น
2. **ใส่ข้อย่อยครบทุกข้อ** — ทำให้โครงการดูครอบคลุมแต่ไม่จริง ให้เฉพาะข้อย่อยที่กิจกรรมตอบได้
3. **งบรวมไม่ตรงกัน** — ต้องไล่ตรวจทุกสมการก่อนส่ง ไม่ใช่แค่ยอดสุดท้าย
4. **ลืม ZWSP นอกตาราง** — ตรวจเฉพาะในตารางแล้วนับว่าผ่าน ไม่พอ
5. **ใช้ `noProof`** เพราะจำสลับกับสกิลบันทึกข้อความ/ข้อสอบ — งานโครงการห้าม

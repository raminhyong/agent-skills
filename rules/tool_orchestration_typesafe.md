# การเลือกใช้เครื่องมือ ปลั๊กอิน และ Extension ด้วยกระบวนการ TypeSafe (Tool Orchestration)

เมื่อต้องสร้างโปรเจกต์ใหม่ หรือต้องแก้ปัญหาที่มีความซับซ้อน ห้ามเดาสุ่มหรือจำกัดตัวเองอยู่แค่เครื่องมือพื้นฐาน ให้ประยุกต์ใช้กรอบคิดและกระบวนการตัดสินใจของ `typesafe-ai` (System One / Jev Structured Judgments) ในการคัดเลือกและเชื่อมต่อเครื่องมือดังนี้:

## 1. วิเคราะห์สภาพปัญหาและบริบท (State Preparation)
* กำหนดสถานะและเป้าหมายที่แท้จริงของโปรเจกต์/ปัญหาให้ชัดเจน (เช่น Tech Stack, ข้อมูลนำเข้า, ผลลัพธ์ที่คาดหวัง, ข้อจำกัดของระบบ)
* ตรวจสอบว่างานนี้เป็นงานสร้างระบบใหม่ (Scaffolding), การขยายฟีเจอร์ (Extension), การแก้จุดบกพร่อง (Debugging), หรือการประมวลผลข้อมูล/เอกสาร

## 2. รวบรวมเครื่องมือที่เป็นตัวเลือก (Candidate Pool)
สำรวจทรัพยากรทั้งหมดในระบบอย่างครอบคลุม:
* **Skills ประจำเครื่อง**: เช่น `typesafe-ai`, `thai-doc`, `build-learning-webapp`, `building-data-apps`, `prepare-piles-print-cards`, ฯลฯ
* **Plugins / Extensions / MCP Servers**: ปลั๊กอินเสริม, MCP tools, และ sidecars ที่ติดตั้งไว้
* **Built-in CLI / SDKs / External Libraries**: เครื่องมือเฉพาะทาง เช่น Python SDKs, npm packages, APIs

## 3. ตัดสินใจและจัดอันดับด้วยตรรกะ System One (Selection & Ranking)
ประยุกต์ใช้ Primitives ของ TypeSafe ในการตัดสินใจ:
* **Choice**: เมื่อมีหลายแนวทาง/เครื่องมือที่แข่งขันกัน ให้เปรียบเทียบข้อดี-ข้อเสีย แล้วเลือกเครื่องมือที่ตรงและมีประสิทธิภาพสูงสุด
* **Noul**: ตรวจสอบเงื่อนไขบังคับ (Gate check) เช่น "เครื่องมือนี้รองรับข้อกำหนดของภาษาไทย/ระบบปฏิบัติการหรือไม่?" (Yes/No)
* **Score**: ให้คะแนนเครื่องมือตามเกณฑ์ เช่น ความเร็ว (Speed), ความถูกต้องแม่นยำ (Accuracy), ความซับซ้อนในการติดตั้ง (Setup Overhead)

## 4. ประสานการทำงานและจัดการ Fallback (Execution & Orchestration)
* ผสานโค้ดและเครื่องมือเข้าด้วยกันอย่างลื่นไหล
* หากเครื่องมือใดเข้าถึงไม่ได้ หรือขาด credentials/dependencies ให้ประเมินและสลับไปใช้ fallback tool ที่ดีที่สุดใน candidate pool ทันทีโดยไม่สะดุด

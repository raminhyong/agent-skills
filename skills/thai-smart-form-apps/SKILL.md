# แอปกรอกแบบฟอร์มราชการ (Thai PW Hub · smart-form-filler)

ใช้เมื่อแตะแอปที่ให้ครูกรอกฟอร์มแล้วได้เอกสาร A4 — โดยเฉพาะ `apps/smart-form-filler`
หลักคิดเดียวที่คุมทุกข้อ: **ถามเฉพาะสิ่งที่ระบบเดาไม่ได้**

## When to Use (ใช้เมื่อไหร่)

- แก้/เพิ่ม แบบฟอร์ม ใน `apps/smart-form-filler` หรือแอปที่กรอกแล้วออกร่างเอกสาร
- งาน **โครง Hub**: แถบบนของแอปย่อย, เมนู/หมวด, Runner, URL state, ปุ่มออกจากระบบ, การปักหมุด/ตั้งค่ากลาง
- ผู้ใช้บอกว่า "ช่องกรอกเยอะไป / ขอ dropdown / ทำไมไม่ดึงข้อมูลนักเรียน-ครู-วิชา"
- งานที่เกี่ยวกับ ปีการศึกษา · ภาคเรียน · วันที่ · วิชา · ผู้ลงนาม ในฟอร์ม
- ต้องแก้พรีวิว A4 / การแบ่งหน้า / การพิมพ์ / การดาวน์โหลด .docx ของฟอร์ม

ไม่ใช้กับ: เอกสารบันทึกข้อความโดยตรง → ใช้ `thai-official-memo` · มาตรฐานตัวอักษร/ตาราง → `thai-doc`

ถ้าผู้ใช้บอก "เคยบอกแล้ว / ย้ำหลายรอบ" → **หยุดเดา ไปอ่านไฟล์ในตารางนี้ก่อน**

## 1) กติกา "กรอกน้อยที่สุด"

1. **ค่าคงที่ของเอกสาร → เขียนลงเอกสารเลย ไม่มีช่องกรอก** (ส่วนราชการ, เรื่อง, เรียน, กลุ่มสาระ, ตำแหน่ง/วิทยฐานะ, สิ่งที่ส่งมาด้วย)
2. **ค่าที่ derive ได้ → ล็อก/คำนวณให้**: ชื่อ-ชั้น-ห้อง จากรหัสนักเรียน · ชั้น-ห้อง จากนักเรียนคนแรก · ยอดรวมคะแนน · ลำดับที่
3. **ช่องที่เหลือต้องเป็นการเลือก ไม่ใช่พิมพ์**: ปี · ภาคเรียน · วิชา · ครู · นักเรียน · วันที่
4. **ห้ามมีเมนู "ผู้ลงนาม" แยก** — ผู้ลงนาม = ครูที่เลือก (ตั้งชื่อ + `ครู วิทยฐานะ…` อัตโนมัติ)
5. ช่องล็อกใช้ `readOnly` + พื้นเทา (`is-locked`) ไม่ใช่ `disabled`

เกณฑ์ตัวเลขที่ผ่านจริง: บันทึกส่งวิจัย 13 → 4 · แบบปรับ-ร 8 → 4 · หลักฐานการเรียนซ้ำ 19 → 14

## 2) ปีการศึกษา / ภาคเรียน / วันที่

- **ปี + ภาค = dropdown 2 ตัว บรรทัดเดียวกัน** · ปีเริ่ม **2569** · **แสดงเฉพาะเลข `1`/`2`** (ห้ามใส่ช่วงวันที่ — ครูรู้อยู่แล้ว)
- ตรรกะ `academic-calendar.js`: ภาค 1 = 1 พ.ค.–31 ต.ค. ปีนี้ · ภาค 2 = 1 พ.ย.–31 ธ.ค. ปีนี้ และ 1 ม.ค.–30 เม.ย. **ปีก่อน (−1)** → ตั้งต้นตามวันนี้
- **วันที่ = ช่องคลิกแล้วเปิดปฏิทินไทย (พ.ศ.)** · ค่าเริ่มต้นวันนี้ · เขียนลงเอกสารเป็น `1 พฤศจิกายน 2569` (ห้าม ค.ศ.)
- วันที่ในเอกสารอยู่ที่ **50%** ของความกว้างเนื้อหา

## 4) พรีวิว A4 + พิมพ์

- แผ่นละ **794×1123 px** · แบ่งหน้าจริง (เนื้อหา 1027 px / 999 px สำหรับ memo ที่ขอบบน 2.0 ซม.)
- ป้าย `หน้า n / N` + เส้นประ (ซ่อนตอนพิมพ์)
- **ตารางยาว: ตัดรายแถว + คัดลอก `thead` ไปทุกหน้า**
- พิมพ์: `@page{size:A4;margin:0}` + `break-after:page` · ความสูงต่อหน้าตรงกับบนจอ
- debounce พรีวิว ~90 ms
- **ย่อให้พอดีช่องพรีวิวด้วย `zoom` เท่านั้น ห้ามใช้ `transform: scale()`** — transform ไม่กระทบ layout กระดาษ 794px จึงยังกินความกว้างเต็ม → เกิดสกอลแนวนอนและ probe มือถือฟ้อง `bodyScrollW` เกิน; `zoom` reflow จริงแล้วหายสนิท
  ```js
  function fitSheet(){ const s = Math.min(1, (stage.clientWidth - 16) / 794); sheet.style.zoom = s < 0.995 ? String(s) : ""; }
  ```
  เรียก `requestAnimationFrame(fitSheet)` ท้ายทุกครั้งที่ `innerHTML` ของแผ่นถูกเขียนใหม่ + ผูก `window.resize` + ให้ปุ่ม ＋/－ เก็บ `userZoom` (null = พอดีจออัตโนมัติ) · **พิมพ์ต้อง `zoom:1 !important`** ไม่งั้นได้กระดาษจิ๋ว
- แผงพรีวิวต้องมีปุ่ม **พิมพ์/PDF · − · พอดีจอ · ＋** — ครูอ่านตัวเล็กไม่ไหวถ้ามีแต่พอดีจอ
- **ถ้าผู้ใช้บอกว่า "ไม่ต้องแสดงพรีวิวก็ได้ แต่ให้โหลดออกมาแล้วถูกต้อง" → หยุดสร้างพรีวิว HTML แล้วเปลี่ยนไปใช้ `.docx` ต้นฉบับเป็นแม่แบบเติมค่า** (JSZip แก้ `word/document.xml`) เพราะการวาดใหม่จากความจำทำให้ฟอร์มเพี้ยน (ตรา/เส้น `=====`/ตาราง 3-5-3 คอลัมน์/บล็อกลงชื่อ 4 ท่อน+ผลพิจารณา ผอ. หายหมด) — วิธีอ่านสเปกและจุดแทนค่า: สกิล `thai-doc` → `references/official-form-replication.md`

## 5) รายการฟอร์ม + แหล่งข้อมูล

- นับ **ตามเอกสารจริง** ไม่ใช่ไฟล์ (`.docx`+`.pdf` เรื่องเดียว = 1 ฟอร์ม)
- **ห้ามใส่ `(PDF)` ในชื่อรายการ** — แสดงชนิดไฟล์ในบรรทัดคำอธิบาย
- "แหล่งข้อมูล" = **ลิงก์หน้าเว็บโรงเรียนจุดเดียว**
- ลบฟอร์ม = ลบทุกที่: dropdown + เทมเพลต + ไฟล์สำเนา + D1 + `manifest.json` + seed SQL + `apps_registry.json`

## 6) กับดักที่เคยพลาด

1. `w:before="120"` ต้องมี **3 จุดเท่านั้น** (8px × 3) — หัวข้ออื่นใช้ 140
2. **ห้ามแทรกข้อความที่ระบบสร้าง** (เครดิต/"* สร้างจาก…")
3. **ห้ามใส่ `/` ในบรรทัด `ที่`** — จุดไข่ปลาล้วน ไม่มีช่องกรอก
4. เพิ่มแถวรัว ๆ ทำพรีวิวค้าง → ต้อง debounce + วัด `scrollHeight` ว่าไม่ล้นหน้า
5. **`.docx` ต้องตรวจจากไฟล์จริง** (Word COM → PDF → PNG หรือ `verify_docx_spacing.py`) ไม่ใช่ดูจากโค้ด
6. ถ้ามี reset เช่น `.a4-sheet div{margin:0}` ต้องเขียนกฎเป็น `.a4-page .xxx` ให้ชนะ
7. **ปีกกาเกิน/ขาด 1 ตัว = ทั้งแอปตายเงียบ** — `app.js` ที่ syntax error จะไม่ถูก execute เลย: ดรอปดาวน์ว่าง, พรีวิว A4 โล่ง, ปุ่มทุกปุ่มกดไม่ติด และ **ไม่มีข้อความ error ขึ้นหน้าจอ** (มีแค่ใน console) → อาการที่ผู้ใช้เรียกว่า "ยังไม่ได้ทำ / เสียหาย" ให้สงสัย syntax เป็นอันดับแรก
8. **การแก้ไฟล์ด้วยสคริปต์แบบ "แทรกก่อนวงเล็บปิดตัวสุดท้าย" (rfind `}`) พลาดง่ายมาก** — เคยแทรกไปในเมธอดผิดจนเรียกตัวเองวนไม่รู้จบ และเคยทิ้ง `}` เกินจนทั้งแอปไม่รัน → หลัง patch แบบสคริปต์ ต้องผ่านด่าน syntax (หัวข้อ 7) ทุกครั้ง ไม่มีข้อยกเว้น
9. **`grid-template-columns: 1fr` บนจอแคบไม่พอ — ต้อง `minmax(0,1fr)`** เพราะค่า min-content ของการ์ด/กระดาษดันคอลัมน์ให้กว้างเกินจอ (เจอ overflow ค้าง 3px ที่ `body.scrollWidth` แม้ `overflow-x:hidden` แล้ว) · จอแคบให้ยุบเมนูซ้ายเหลือเฉพาะหัวข้อ (ซ่อนรายการย่อย `#sub1/#sub2`) เพราะรายการเต็มอยู่ตรงกลางแล้ว ไม่งั้นเมนูกินพื้นที่จอแรกทั้งหน้า
10. **ปุ่มที่ถูกล็อกด้วยค่าฟิลด์ ต้องอัปเดตตัวเองทันทีที่ค่าเปลี่ยน** (ไม่ใช่คำนวณ `disabled` แค่ตอน render แรก) — เขียน `updateGatedButtons()` เรียกจาก handler ของฟิลด์นั้น
11. **เปลี่ยนโครงข้อมูลที่เก็บ → ต้องเปลี่ยน `localStorage` key และตรวจชนิดตอนโหลด**
    ```js
    if (EDITS.projects || EDITS.year) { EDITS = {}; localStorage.removeItem(LS_KEY); }
    ```
    ไม่ทำ = ของเก่าที่เป็นทั้งก้อน DB ถูกอ่านเป็น "ส่วนที่แก้" → ตัวเลขเพี้ยนเงียบ ๆ ได้โดยไม่มี error (งบ 15,000 กลายเป็น 15,003)
12. **ดึงฟิลด์จากเอกสารด้วย `startswith` ตรง ๆ พลาดเรื่อย** — `ชื่อโครงการหลัก` ขึ้นต้นด้วย `ชื่อโครงการ` → ใช้ `^ชื่อโครงการ(?!หลัก)`; บรรทัดที่มีเลขข้อ (`3. เงินอื่น ๆ`) ต้องตัดเลขข้อก่อนอ่านจำนวน; แถว `รวม…` ท้ายตารางต้องกรองทิ้ง; **แถวที่เซลล์เดียวบรรจุหลายรายการ (เซลล์ merged) อย่าแยกด้วยช่องว่าง** — เก็บเป็น 1 บรรทัดพร้อมฟิลด์ `amount` = ผลรวมจากเอกสาร แล้วให้ `itemsTotal()` ใช้ `amount` ถ้ามี (แก้ qty/price แล้วค่อย `delete amount`) ไม่งั้นยอดรวมจะไม่เท่างบ (เจอเคส 5,840 → 1,840)

## 7) ตรวจรับก่อนรายงาน

```
[ ] ไม่มีช่องสำหรับค่าคงที่ · ไม่มีเมนู "ผู้ลงนาม" · ช่องที่เหลือเป็นการเลือก ยกเว้นรหัสนักเรียน/ชื่อเรื่อง
[ ] dropdown วิชากรองตามภาค (นับจำนวนถูก) · เลือกวิชาแล้วครูขึ้นเอง
[ ] วันที่: คลิกแล้วปฏิทินเปิด · ค่าเริ่มต้นวันนี้ · เอกสารเป็น พ.ศ.
[ ] พรีวิว 794×1123 · ป้ายหน้า n/N · ไม่มี overflow · ตารางมี thead ทุกหน้า
[ ] Word: TH Sarabun New 100% · memo 1 หน้า · 8px = 3 จุด · ชื่อผู้บริหารครบ
[ ] มือถือ 390px: หลุดจอ 0 · ปุ่มเล็ก 0% · ฟอนต์ <12px 0 · ไม่มีสกอลแนวนอน
[ ] node --check ผ่านทุกไฟล์ JS ที่แก้ + sweep ทั้ง apps/ ได้ 0 broken  ← ก่อน deploy เสมอ
```

```bash
# ด่าน syntax ก่อน deploy (ทำทุกครั้งที่แก้ .js — 1 วินาที)
node --check apps/<app>/js/app.js || echo BROKEN
# sweep ทั้งโปรเจกต์ (ตัด bundle/min ออก)
for f in $(find apps js assets/js -name "*.js" ! -name "*bundle*" ! -name "*.min.js"); do
  node --check "$f" 2>/dev/null || echo "BROKEN: $f"
done
```

**คู่มือซ่อมเมื่อผู้ใช้บอก "แอปนี้เสีย / ยังไม่ได้ทำ"** (ทำตามลำดับ ห้ามเดา):
1. `node --check` ไฟล์ JS ของแอปนั้น → เจอ syntax error = จบเคส แก้แล้ว deploy
2. ถ้าผ่าน: ในหน้าเว็บจริง `fetch(url)` → `new Function(src)` เพื่อจับ syntax ของ **ไฟล์ที่ deploy แล้ว** (อาจไม่ตรงกับ local)
3. เช็ค global ที่แอปพึ่งพา: `typeof window.MEMO_DATA`, `window.MEMO_DOCX_BUILDER`, `window.SyllabusData`, `THAI_COURSES_RICH` — ถ้า `undefined` คือสคริปต์ต้นทางไม่รัน
4. นับ DOM ที่ควรมี: จำนวน `select.options`, `.a4-sheet`, ปุ่มสำคัญ — ถ้าเป็น 0 แปลว่า JS ไม่ได้ทำงาน ไม่ใช่ "ฟีเจอร์ยังไม่ทำ"
5. ซ่อมแล้วพิสูจน์ด้วยของจริง: จำนวนตัวเลือก, จำนวนแผ่น A4, และ **ดาวน์โหลด .docx ได้กี่ไบต์** (ดัก `URL.createObjectURL` + `HTMLAnchorElement.click` ในคอนโซลเพื่อยืนยันโดยไม่ต้องโหลดไฟล์)

**รายงานกลับเป็นตาราง**: `สิ่งที่แก้ → ค่าที่วัดได้ → หลักฐาน` ไม่ใช่คำว่า "เรียบร้อยแล้ว"

## 8) แถบบนมาตรฐานของทุกแอป (Thai PW Hub) — ใช้เหมือนกันหมด

ทุกแอปย่อยโหลด `css/app-topbar.css` + `js/app-topbar.js` จาก root — สคริปต์จะ **สร้างแถบใหม่และแทนที่ของเดิมเอง** ไม่ต้องแก้ markup รายแอป
- ซ้าย: โลโก้ย่อย (badge 44px) → **ชื่อไทย (บน) / ชื่ออังกฤษ (ล่าง)** — **ห้ามมี "กลุ่มสาระการเรียนรู้ภาษาไทย"**
- ขวา: **ปุ่มวงกลมล้วน ไม่มีข้อความ** — สเปกจริงอยู่ในหัวข้อถัดไป (ห้ามกลับไปใช้ 🏠 / ↻ / ⛶ / วงเล็บมุม)
- **ห้ามมีป้าย "พร้อมใช้งาน"** และห้ามมีสองแถบซ้อน
- ชื่อ/ไอคอน/เมนูปลายทาง อยู่ที่ `data/app_topbars.json` (19 แอป) — เพิ่มแอปใหม่ = เพิ่ม 1 entry
- ปุ่มเฉพาะของแอป (เช่น ดาวน์โหลด PDF) ถูกย้ายเข้าแถบเป็น `.atb-extra` อัตโนมัติ (ซ่อนบนจอ <900px) — **ย้ายเฉพาะปุ่มที่มีชื่อ >=3 ตัวอักษร** ปุ่มไอคอนล้วน (↻ ⛶ ＋) ต้องทิ้ง ไม่งั้นได้ 4–5 ปุ่มซ้ำในแถบเดียว
- **สเปกที่เจ๊อนุมัติ (ห้ามเปลี่ยนเอง)**: วงกลม 38px (มือถือ 44) ทั้ง 4 ปุ่ม เรียง `[X ปิด] [รีเฟรช] [แชร์] [ขยาย/ย่อ]` — ปุ่มแรก **X สีไวน์พื้นขาว** ทำหน้าที่เดิมคือกลับเมนูย่อย (`target=_top`); 1) **รีเฟรช** = ลูกศรวน 2 ตัว (sync) 2) **แชร์** = สี่เหลี่ยมมีลูกศรพุ่งออก (`navigator.share` → fallback คัดลอกลิงก์ + toast) 3) **ขยาย/ย่อ** = วงกลมพื้นครีม ลูกศรชี้ออก 2/8 นาฬิกา, เมื่อขยายอยู่ชี้เข้า — ห้ามใส่ข้อความในการปุ่ม (ห้ามมีคำว่า กลับ/Y่อ/ขยาย) ห้ามใช้ glyph/emoji
- มือถือ ≤430px: ชื่อไทยให้ขึ้นได้ 2 บรรทัด (line-clamp 2) ดีกว่าตัดด้วย … — แต่ห้ามย่อปุ่มต่ำกว่า 44px (tap floor ของ `mobile-kit.js` จะดันกลับ)
- **รูปไอคอน: ลอกจากภาพที่ผู้ใช้ส่งให้เป๊ะ ๆ** — ถ้าภาพมีหลายปุ่มที่หน้าตาคล้ายกัน ให้ทวน "ไอคอนไหน = ปุ่มอะไร" กับผู้ใช้ก่อนเขียนโค้ด (ภาพชุดเดียวตีความได้เป็น refresh+fullscreen แต่ของจริงคือ refresh + share + expand) แล้วเขียน SVG ตามรูปทรงนั้น ห้ามออกแบบไอคอนเองแล้วรายงานว่าทำตามภาพ
- **ห้ามอ้าง "ทำไม่ได้" เมื่อมันเป็นแค่ทางเลือกของเรา** — ถ้าผู้ใช้ถามว่าทำไมทำไม่ได้ ให้ตรวจก่อน: ถ้าทำได้ให้ตอบตรง ๆ ว่าเลือกผิดเอง แล้วลงมือทำทันที (การอ้างข้อจำกัดปลอมเสียเครดิตมากกว่าการรับผิด)
- **ปุ่มกลับ/โลโก้ ต้อง `target="_top"`** (และ sweep `a[href*=index.html]` ให้เป็น `_top` ทุกตัว) — ไม่งั้นกดกลับใน iframe ของ Hub แล้ว Hub ซ้อนใน Hub เอง 2-3-4 ชั้น เพิ่มขึ้นเรื่อย ๆ ทุกครั้งที่กด
- **แอปที่มี A4 หลายหน้า: mobile-kit ย่อได้ต้องให้ `.a4-pages` กว้าง `794px`** (ห้าม 100%) เพราะ `applySheetScale()` ใช้ `offsetWidth` เป็นความกว้างจริง; ถ้าเป็น 100% จะได้ scale≈1 แล้วเอกสารล้นขวาบนมือถือ
- Hub อ่านสถานะจาก URL ที่ `ThaiSuperApp.applyUrlState()` (`?cat=&sub&q&app`) → เปิดเมนูย่อย/แอปที่ผู้ใช้มาจากได้ และ **ห้ามล้าง query ออกหลังอ่านค่า** (ดูกฎในหัวข้อ 10)
- CSS ใหม่ต้องวาง **ท้าย `<head>`** เพื่อชนะธีมกลาง/`mobile-kit.css` (ไม่งั้นมือถือจะดันปุ่มลงบรรทัดใหม่)

## 9) ตั้งค่าส่วนกลางของทั้งเว็บ (ปักหมุด) — เก็บที่เซิร์ฟเวอร์ ไม่ใช่ localStorage

"ตั้งค่าเว็บโดยรวม" (ปักหมุด / ลำดับเมนู / ค่าเริ่มต้น) ต้อง **เก็บที่เซิร์ฟเวอร์** เพื่อให้ทุกเครื่องเห็นเหมือนกัน
แต่ **เขียนได้เฉพาะผู้ดูแล** ด้วยรหัสลับ:

```
GET  https://thai-hub-pins.raminhyong.workers.dev/api/pins        → { pins: [...] }   (ทุกคนอ่าน)
POST /api/pins  {action:"pin"|"unpin", id}  + header x-admin-pin  → 401 ถ้ารหัสผิด
```

- Worker: `workers/pins-api/` (D1 binding `DB` → ตาราง `hub_pins(app_id PK, pinned_at)`) · รหัสเก็บเป็น **Cloudflare secret `ADMIN_PIN`** (ห้ามอยู่ในโค้ด/รีโป)
- หน้าบ้าน `js/app.js`: `loadPins()` ตอน init → `togglePin()` → ถ้าไม่มี session ผู้ดูแลให้เปิด `showAdminDialog()` แล้วค่อย `pushPin()`; จำสถานะปลดล็อกใน `sessionStorage`
- `localStorage` ใช้เป็น **แคชอ่านอย่างเดียว** (เน็ตหลุดยังเห็นรายการ) ไม่ใช่แหล่งจริง
- `app_id` ต้องตรงกับ `id` ใน `data/apps_registry.json` ไม่งั้นแถวจะค้างโดยไม่มีอะไรแสดง

สูตรเต็ม (Worker + secret + curl ทดสอบ + เปลี่ยนรหัส) อยู่ที่ `references/hub-global-settings.md`

## 10) สถานะหน้าจอ ↔ URL · ปุ่มออกจากระบบ

- **"อยู่หน้าไหน รีเฟรชแล้วต้องอยู่หน้านั้น"** — เก็บ `cat`, `sub`, `q` (คำค้น), `app` (id ที่เปิดใน Runner) ลง query และเขียนด้วย `history.replaceState` ทุกครั้งที่เปลี่ยนหน้า
- **ห้ามล้าง query ออกจาก URL หลังอ่านค่า** — นั่นคือสาเหตุที่ F5 แล้วเด้งกลับหน้าแรก (บั๊กที่ผู้ใช้จับได้ทันที)
- ฟังก์ชันคู่กัน: `syncUrlState()` เขียน ↔ `applyUrlState()` อ่าน/คืนค่า (เรียกท้าย `init()`) — ชื่อเดิม `applyDeepLink()` ยกเลิกแล้ว
- Runner ต้องประกาศสถานะ: `notifyState()` ยิง event `hub:runner` ท้าย `launch()` **และ** `close()` → `js/app.js` ฟังแล้วเรียก `syncUrlState()`
- `?app=` ต้องตรวจว่ามี id ใน registry และไม่ใช่ `isComingSoon` ก่อน `launch()`
- **กับดัก recursion**: อย่าแทรก `this.notifyState();` "ท้ายเมธอด" ด้วยการสแกนวงเล็บปิด — ถ้าพลาดจะไปเรียกตัวเองภายใน `notifyState()` → `Maximum call stack size exceeded` และ **เมนูทั้งแถบกดไม่ติดแบบเงียบ ๆ** (ไม่มี error บนหน้าจอ). หลังแทรกโค้ดทุกครั้ง: `node --check` แล้วเปิดหน้า คลิกเมนู 1 ครั้งดูว่าสถานะเปลี่ยน
- Debug handle: ผูก `window.hubApp = app` ตอนสร้าง instance — ใช้ `hubApp.selectSubcategory(...)` / อ่าน `hubApp.currentCategory` ในคอนโซล
- ปุ่ม **ออกจากระบบ** = วงกลมขนาดเดียวกับปุ่มมืด/สว่าง วางติดกัน: ล้าง `sessionStorage` ของ gate + สิทธิ์ผู้ดูแล แล้ว `location.replace(pathname)` → กลับไปหน้ากล่องรหัส (รายการปักหมุดไม่หาย เพราะอยู่ที่เซิร์ฟเวอร์)

สูตรเต็ม (ตารางพารามิเตอร์ + จุดเชื่อม Runner + ชุดทดสอบ) อยู่ที่ `references/hub-shell-navigation.md`

## 11) สร้างแอปใหม่ / ออกแบบโครงเมนู

ลำดับงานตายตัว (อย่าข้ามไปเขียนโค้ดก่อน): **อ่านของจริง → นับด้วยสคริปต์ → เสนอโครงเมนู + mockup → รออนุมัติ → P1 deploy → P2 ต่อยอด**

- **โครงเมนูยึดคำสั่งผู้ใช้ในเทิร์นล่าสุด ไม่ใช่การจัดกลุ่มของเอกสารต้นทาง** — เอกสารโรงเรียนมักจัดตามกลยุทธ์/โครงการหลัก แต่ถ้าเจ้าของงานบอก "แยกตามภาคเรียน" ต้องแยกตามภาคเรียนทันที
- **ตรวจ `data/apps_registry.json` ก่อนสร้างแอป** — รายการที่ `url` เป็น `example.com` = ยังไม่มีแอป (placeholder) และมักมีหลายรายการซ้ำในหมวดเดียว → รายงานให้ผู้ใช้เห็นแล้วเสนอ **ยุบให้เหลือชุดเดียว** อย่าเพิ่มรายการที่ 6 ทับของเดิม
- **ผู้ใช้ต้องการ mockup ก่อนอนุมัติเขียนโค้ดเสมอ** — mockup เก็บที่ `docs/mockups/`, เปิดในเบราว์เซอร์จริง + screenshot ตรวจก่อนส่ง และแสดงผ่าน `::preview{file="…"}` ในแชท
- **ห้ามถามคำถามที่คำตอบอยู่ในคำสั่งเดิมหรือมีคำตอบเดียวที่ถูก** — เช่น ถ้าผู้ใช้บอก "ให้ออกมาเหมือนไฟล์ตัวอย่าง" ก็คือ "สะท้อนทุกค่าที่กรอก" แล้ว ไม่ต้องย้อนถามว่าให้สะท้อนค่าอะไร; คำถามแบบนี้ทำให้เสียเวลาผู้ใช้และถูกดุว่า "ตัดสินใจเรื่องแค่นี้ไม่ได้หรอ" · ถามเฉพาะเมื่อคำตอบ **เปลี่ยนสิ่งที่จะสร้างจริง** (เช่น ขนาดกระดาษ A4/Letter ที่กระทบทุกหน้า) และถามได้ครั้งเดียวต่อเรื่อง
- **ตัวเลขในรายงานต้องมาจากการนับจริง** (สคริปต์อ่านไฟล์) ไม่ใช่การกะจากรายชื่อไฟล์; เรื่องที่ผู้ใช้บอกว่า "ไม่ต้องสนใจ" (เช่น ยอดเงิน) ห้ามเอามาเป็นแกนตัดสินใจหรือถามซ้ำ
- **แอปงานโครงการ/งานประจำปี**: โครงข้อมูลต้องมี 3 ชั้น (แม่แบบโครงการ → ฉบับรายปี/รายภาค → รายการวัสดุที่เปลี่ยนทุกปี) + ปุ่ม "คัดลอกทั้งชุดจากปีก่อน" + ลิงก์ส่งต่อ `?y=&t=&p=` ไปแอปถัดไปในสายงาน

### ข้อมูลมีอยู่แล้วในเอกสาร → ห้ามสร้างฟอร์มเปล่า (กฎเหล็ก)

ถ้าโฟลเดอร์ต้นทางมี `.docx` ของโครงการ/ฟอร์มครบแล้ว ระบบต้อง **เปิดมาแล้วมีเนื้อหาครบ** ผู้ใช้แก้เฉพาะส่วนที่เปลี่ยน (งบ/รายการวัสดุ/ผู้รับผิดชอบ/สถานะ)

1. **แยกเนื้อหาออกมาเป็น seed JSON** (`apps/<app>/data/projects-<year>.json`) ด้วย `scripts/docx_blocks.py` — อย่าให้ผู้ใช้พิมพ์ซ้ำสิ่งที่ไฟล์มีอยู่ (นี่คือข้อที่ผู้ใช้ตำหนิหนักที่สุด: "ทำไมฉันต้องกรอกข้อมูลเหล่านี้ ในเมื่อมันมีอยู่แล้ว")
2. **UI = อ่านอย่างเดียว + แก้เฉพาะตัวแปร**: การ์ด "ข้อมูลที่มีอยู่แล้วในเอกสาร" (หลักการ/วัตถุประสงค์/เป้าหมาย/กิจกรรม/ตัวชี้วัด) → งบ/รายการวัสดุ (แก้ได้) → `<details>` ✏️ สำหรับข้อความบรรยาย
3. **ต้องมีปุ่ม ↺ คืนค่าจากต้นฉบับ** ต่อรายการ
4. **เก็บเฉพาะ diff** (`EDITS` ทับ seed ตอน boot) — seed เป็น read-only ที่ commit ขึ้น repo
5. **ตรวจด้วยผลรวม**: `sum(items) == budget.total` ทุกฉบับก่อนรายงาน — ไม่ตรง = ยัง parse พลาด ห้ามบอกว่าเสร็จ

สูตรเต็ม (แผนที่ฟิลด์, 7 กับดักการ parse, ตรวจคุณภาพ): `references/docx-to-seed-json.md`
สคริปต์อ่าน `.docx` เป็น block รวมตาราง: `scripts/docx_blocks.py`

รายละเอียด (โครงการ 3 ชั้น, ชุดนโยบายรายปี, สายงาน เสนอ→ขออนุญาต→รายงานผล, วิธีสรุปข้อมูลจากกองเอกสาร): `references/hub-app-authoring-workflow.md`
สครับต์แยกข้อความ `.docx` แบบไม่ต้องมี python-docx: `scripts/extract_docx_text.py`

## 11) กับดักการตรวจงาน (จำไว้ — เคยพลาดมาแล้ว)

| กับดัก | อาการ | วิธีตรวจที่ถูก |
|---|---|---|
| **ตรวจในเบราว์เซอร์ที่มี localStorage ของเราเอง** | เห็นค่าที่แก้แล้ว → สรุปว่าข้อมูลจริงเปลี่ยนแล้ว → ผู้ใช้เปิดมาเห็น “รอเสนอ” | `localStorage.clear(); sessionStorage.clear();` แล้วโหลดใหม่ **ก่อนอ้างว่าผ่าน** |

| แก้ข้อมูล seed แต่ลืม deploy | หน้าเว็บยังเป็นค่าเดิม | หลังแก้ JSON ต้อง deploy + ตรวจด้วย storage ว่าง |
| อ้างว่าผ่านโดยไม่เห็น output | เคส “สถานะยังเป็น รอเสนอ” | ต้องมี output ของค่าที่อ่านจากหน้าจอ/API ในข้อความนั้น ก่อนพูดว่าสำเร็จ |

## 13) เติมค่าลง .docx แบบ template-fill (บทเรียนจริง)

เมื่อใช้ไฟล์ราชการเป็นแม่แบบแล้วแทนค่าใน `word/document.xml`: **ห้ามเชื่อ XML — ต้อง render ทุกหน้าดูด้วยตา** (Word COM → PDF → PNG)

| กันดัก | อาการที่เจอ | วิธีแก้ |
|---|---|---|
| กระดาษต้นฉบับเป็น **Letter** (12240×15840) | เส้น `======` ล้นขึ้นบรรทัดใหม่, page break เดิมทำให้เกิด **หน้าว่าง** | แปลงเป็น A4 + ย่อเส้นคั่น (66 ตัวอักษร) + **ลบ `w:br type=page` ทั้งหมด** |
| ใส่ `\t` ลงใน `<w:t>` | ตัวเลขไปโผล่ต้นบรรทัด/ทับเลขลำดับ | ห้ามสร้างย่อหน้าใหม่ — **แทนเฉพาะ run ที่เป็นตัวเลข** (`/^[\d,]+$/`) ข้าม run ที่เป็นเลขลำดับ `1.` `2.` |
| เลข 0 | ไปทับจุดไข่ปลา `.....-....บาท` ของฟอร์ม | ค่า 0 → **ไม่แตะ** ปล่อยจุดไข่ปลาตามต้นฉบับ |
| ตารางข้ามหน้า | หน้าใหม่ไม่มีหัวตาราง | ใส่ `w:tblHeader` ที่แถวหัว (ทั้งตารางกิจกรรม/วัสดุ/ประเมิน) |
| บล็อกลงชื่อขาดหน้า | หัวข้ออยู่หน้าหนึ่ง ช่อง [ ] อยู่อีกหน้า | `keep_with_next` เฉพาะบรรทัดในบล็อก (นับจำนวนบรรทัดที่มีข้อความ) + `keep_together` |
| keep กว้างเกิน | ลากบรรทัดว่างไปด้วย → หน้าเปล่าเพิ่ม | กำหนดจำนวนบรรทัดต่อบล็อกให้จบ (3 / 6 / 7) |
| ตรวจไม่ครบ | ไฟล์เสีย/หน้าว่างหลุดถึงผู้ใช้ | รัน `tools/verify_project_templates.py` ทุกไฟล์ + render PNG ดูทุกหน้า |
